*Closed* means the kernel accepted the proof and it depends only on `propext`, `Classical.choice` and `Quot.sound`. It says that the statement as written in the file is proved; it does not say that an open problem is solved. Every statement is in `VERIFICACAO.json`. *Conditional* means the proof also uses axioms declared in the repository; *open* means it uses `sorry`. *Checked file by file* covers the files that no build reached: each one went through Lean whole, with a `#print axioms` for each theorem.

**10 104 of the conditional theorems depend on axioms of the MVEI name layer, not on axioms the author wrote.** The generated files use thousands of names that exist nowhere in the repository; the patch `correcoes/vinculo-estrutura.patch` adds `MveiEstrutura/Mishkan.lean`, which links some of them to the author's own definitions, declares the rest as opaque, and states as named axioms the laws the generated proofs apply. These are hypotheses chosen by MVEI to make the files compile. `ConsistenciaMishkan.lean` (in this folder) gives a model of all of them, together with the author's axioms in `FORMAL_VERIFICATIONS.lean`, checked by the kernel: they are consistent, so they do not prove `False`. In that model the opaque types are empty and the opaque predicates are true, so almost all of these axioms, and the theorems that use them, hold vacuously. The files in `semantica/` give, for each axiom of the layer, an interpretation checked by the kernel in which that axiom is false (`ContraA`, `ContraB`, `ContraC`): none of them can be proved from what the repository defines, so these theorems stay conditional. `Dados.lean` checks what the author's own numbers decide: the generated precedences hold for the generator's dates; concept 425 of the generator is dated 1600 and contradicts the author's axiom `modern_mathematics` (> 1600); the 71 `absolute_precedence_N` of `MILLENNIUM_SOLUTIONS.lean` are false as written (they add the negative date instead of subtracting it); the gematria of ישו is 316. The folder `teoria/` gives an interpretation that is NOT vacuous: every opaque name of the layer gets a definition from the corpus data (the 417 catalog signs, 599 generated modern concepts — concept 425 is the one forced exclusion —, the TIMELINE events and milestones, the 600 evidence records, the 417 temple pillars, the seven Millennium problems with the real year each was posed) and every axiom of the layer is proved with the same statement (a `theorem`; the three whose type is data, not a proposition, are definitions). It comes with a grammar of the sign language (grammatical classes, formulas generated by the 27 operator signs of the catalog, a Boolean and S5 semantics over the five sites, a bijective translation to modern notation that preserves meaning), a check of every arithmetic claim of the catalog, and the generators that produce each data table. It is a model chosen by MVEI, not the author's meaning; the theorems that close in it are reported there and are not counted as the author's closed theorems. `teoria/DIVERGENCES.md` lists, with kernel-checked theorems, the four places where the author's text and the kernel disagree (signs 21 and 35 with swapped number classes, concept 425, the precedence of `↔` in `logical_preservation`, the 71 `absolute_precedence_N` that add a negative date instead of subtracting it).

## Files in this folder

* `VERIFICACAO.json` — each Lean project of this repository, each theorem the kernel read, its statement, its axioms and its state (`fechado` closed, `condicional` conditional, `aberto-sorry` open)
* `TEOREMAS.csv` — each declared `theorem`/`lemma`: file, line, state in the kernel (`nao_checado` = not checked) and, if not checked, why (in Portuguese)
* `BUILD_LOG.txt` — one block per project: Lean version, result, errors
* `SOURCE.json` — source commit, verified commit and dates, machine-readable
* `SOURCES.sha256` — SHA-256 of every published file
* `ConsistenciaMishkan.lean` — kernel-checked model of the MVEI name layer's axioms (build it with Lean 4.19 and Mathlib v4.19.0; every axiom of the layer is a `theorem` there, with the same statement)
* `semantica/` — countermodels (`ContraA`, `ContraB`, `ContraC`: each `falha_X : ¬ (…)` has the statement of axiom X) and `Dados.lean` (what the author's numbers decide); same toolchain
* `teoria/` — the concrete interpretation: `MveiEstrutura/Mishkan.lean` (the layer with every name defined and every axiom proved), `MveiEstrutura/Teoria/` (grammar, arithmetic, data and generators), `MveiEstrutura/Divergencias.lean` and `DIVERGENCES.md` (where the author's text and the kernel disagree), `Fechamento/Formal.lean` (the data equal the author's, field by field), `archaeology/HARAPPA_CATALOG.lean` (the author's catalog with the MVEI patches), so that `lake build` works in that folder

## Reproduce

```
cd imports/mishkan-iii-core/<project>   # a project folder from the table above ('.' is imports/mishkan-iii-core)
lake exe cache get           # only for projects that require Mathlib
lake build
```

Each project uses the Lean version in its own `lean-toolchain`, which elan installs. The MVEI pipeline that produced these results is in the author's repository and is not public.
